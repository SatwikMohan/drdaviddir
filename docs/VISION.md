# Local camera perception

The browser voice page now has a **Camera off / Camera on** control. Camera permission is requested only after a click. Browser capture and microphone capture are independent. The camera preview stays hidden; stopping the camera or closing the page stops its media tracks. Use localhost or HTTPS for browser camera permission. **Camera on** means capture is active; wait for **Visual context ready** before asking what the agent sees. The first local model load can take over a minute on this machine. If you ask early, the agent will say that analysis is still in progress.

Run the FastAPI application as before, with one worker. Ollama must run on the same backend machine, since camera images go from the browser to this server and then to the local Ollama HTTP service. No camera image is sent to OpenAI. Start Ollama on Windows with `ollama serve` if its desktop service is not already running. Stop the Ollama service using its desktop app or by stopping that process.

From the repository root, run `.\.venv\Scripts\python.exe -B backend/scripts/setup_vision.py` for complete setup. The script installs Ollama on Windows if missing using its official installer, starts the local service if needed, pulls the configured model if missing, verifies image inference, and reports whether Ollama loaded the model on CPU or GPU. Ollama chooses the device automatically when a supported GPU and enough memory are available; the Python script does not force GPU use. Rerunning it reuses the installed service and model. Use `--check` to check installation, service, and model availability without making changes. The selected `qwen3-vl:2b-instruct-q4_K_M` image model is about 1.9 GB on disk. On machines with limited free memory, inference may be slow or fail; voice continues if this happens. Set `VISION_MODEL` to another installed Ollama image model to switch.

The camera sends a compressed 512 pixel JPEG every three seconds. Each WebSocket session owns one pending frame and one worker. The pending frame is overwritten by newer frames. Small greyscale images suppress duplicate scenes; a 12 second cooldown limits deep analysis, and a 25 second interval refreshes an unchanged scene. One process-wide semaphore limits Ollama inference to one request. Recent observations expire after 45 seconds and are removed when the session ends. The GPT turn reads a cached observation immediately after transcription and never waits on the vision worker. Images are held only in memory during processing. The 180 second timeout covers a slow first model load; a 30 second retry delay prevents repeated failures from saturating the machine. A warm request should usually be much faster.

When the camera is on, the main GPT agent may make a brief spontaneous remark after a notable visual change and at least 10 seconds of user idle time, or may gently invite interaction after 45 seconds of idle time even if the scene is stable. It can also choose `SILENT`. A 90 second cooldown limits GPT and Echo requests. Only one idle invitation is attempted until the user interacts again. The browser reports listening, generating and playback states so proactive speech waits until those activities finish; a user turn cancels pending proactive work. Camera images remain local to Ollama, and only its structured observation reaches GPT. The vision model never speaks directly. This feature uses visual observations, not continuous ambient audio, so it cannot determine what nearby people are saying.

Settings in `backend/config.py` can be changed through `VISION_OLLAMA_URL`, `VISION_MODEL`, `VISION_KEEP_ALIVE`, `VISION_CAPTURE_INTERVAL_MS`, `VISION_FRAME_WIDTH`, `VISION_CHANGE_THRESHOLD`, `VISION_COOLDOWN_SECONDS`, `VISION_PERIODIC_SECONDS`, `VISION_TIMEOUT_SECONDS`, and `VISION_CONTEXT_TTL_SECONDS`. Proactive remarks can be disabled with `VISION_PROACTIVE_ENABLED=0`; their change threshold, minimum confidence, cooldown and idle delays have `VISION_PROACTIVE_*` settings. Keep this backend on a single worker process to retain WebSocket session ownership.

For diagnostics, read `panman.vision` logs for scene inference duration, scene difference and replaced frame count. Compare `panman.turn` STT, first token, and first audible events with camera off and on under the same test conditions. If the camera says permission denied, grant site camera access and use HTTPS or localhost. If vision is unavailable, check `ollama list`, the Ollama service, the configured model and available system memory. The microphone and avatar remain usable when vision is unavailable.

## External USB webcam on another computer

The browser uses the webcam attached to the computer displaying the page; the FastAPI/Ollama machine does not need that camera. Open the application on that computer using an HTTPS URL, or use `http://localhost` when the browser and app server are on the same computer. Plain `http://<server-LAN-IP>:8000` is not a secure browser context and camera permission will not be offered. The bundled Caddyfile is only a localhost template; a remote deployment needs a real HTTPS hostname and certificate.

If the page is secure but the camera still stays off, read the text beside the camera button. A missing-device message means to check that the USB webcam appears in the operating system's camera app. A blocked message means to enable camera permission for the browser/site and in system privacy settings. A busy/unavailable message means to close other apps using the webcam or reconnect it. The app now requests `video:true`, leaving the webcam free to choose a supported capture mode; frames are resized for Ollama after capture.

## Measurements on this Windows machine (14 November 2026)

- 8 logical CPU cores, 8.3 GB RAM, about 435.7 GB free on E: before the model pull.
- Ollama 0.40.16; `qwen3-vl:2b-instruct-q4_K_M` installed at 1.9 GB on disk.
- Generated 320 x 200 text image: cold inference 105.23 seconds, warm inference 6.59 seconds. Both identified visible text. The cold load exceeded the original 30 second timeout; the default is now 180 seconds after a reported timeout under concurrent app use.
- During cold inference, `llama-server` used approximately 2.5 GB RSS; system available RAM fell to about 0.3 GB. CPU sampling reached 58.5% during inference. No GPU/VRAM figure was available from the current tools.
- Browser camera capture and equivalent live audio latency with vision off and on were not measured here. The local camera device and real voice round trip require an interactive browser session. The automated worker test confirms the event loop continues while a simulated inference runs.
